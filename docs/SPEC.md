你是這個專案的長期維護工程師。

第一件事：把這整份規格原文存成 docs/SPEC.md 並 commit。之後我只會說「照 SPEC.md 做」或「SPEC.md 第幾節要改成……」，規格有變動時你要同步更新 SPEC.md。

## 一、目的
- 小狼（幼童軍）和家長：用帳號密碼登入網頁，查入團時間、已拿到與正在挑戰的進程和技能章、還有哪些待挑戰。實際操作的人多半是家長。
- 團長與服務員：同一個網頁、同一種帳號登入後進後台，管理名單、產生綁定碼、簽核完成項目、登錄頒章。
- 團長可以不改程式就指定管理員、調整項目內容、說明文字與各項系統數值。
- 晉級與頒章不自動執行，但條件一滿足要由 LINE 官方帳號主動通知團長；頒發日期由團長設定並記錄。
- 對象是未成年人，個資保護與可刪除性是硬需求，不是加分項。

## 二、技術架構
- 前端：web/index.html（原生 HTML/CSS/JS，不用框架、不用建置工具），部署到 GitHub Pages。查詢端與後台同一頁，依身分顯示不同畫面。家長與管理員都用帳號密碼登入，家長端完全不需要 LINE。
- 後端：Google Apps Script Web App，用 clasp 管理與部署。原始碼放 gas/，可拆成多個 .gs 檔。
- 資料庫：Google 試算表。
- LINE：只用一個 Messaging API channel（官方帳號），用途僅限「通知管理員」與「管理員關鍵字查詢」。不使用 LINE Login 與 LIFF。
- 登入機制：
  - 帳號由使用者自行註冊並選身分（家長／服務員），送出申請由團長審核（附錄第 31 點）；團長發的綁定碼仍可直接註冊。邀請碼只用於第一位團長（附錄第 33 點）。
  - 密碼只存加鹽後多次雜湊的結果，不存明碼，也不寫進任何日誌。
  - 登入成功後由後端產生隨機的登入憑證（工作階段），前端存在瀏覽器，之後每次呼叫 API 都帶上；後端只存憑證的雜湊。憑證有效天數依設定，過期或登出即失效。
  - 忘記密碼：家長聯絡團長，團長在後台產生一次性臨時碼，自行用 LINE 官方帳號傳給家長；家長用帳號＋臨時碼設定新密碼。系統不自動寄送。
- 已知限制，請照這樣處理：
  1. 前端呼叫 GAS 用 fetch POST，Content-Type 設為 text/plain 並在 body 放 JSON，避免 CORS 預檢失敗。
  2. GAS 的 doPost 讀不到請求標頭，無法驗證 X-Line-Signature。改為 webhook 網址帶一個長隨機密鑰參數（存在 Script Properties），不符就直接忽略；並且只處理事件內容格式正確的請求。
  3. doPost 同時接前端 API 與 LINE webhook，依密鑰參數與 body 結構分流。
  4. 單次執行不可超過 GAS 6 分鐘上限；試算表一律批次讀寫（getValues/setValues），不逐格讀寫；寫入用 LockService。
  5. 登入憑證過期或無效時，後端回傳明確的錯誤代碼；前端收到後清除憑證、回到登入畫面，登入後自動回到原本的畫面，不顯示技術性錯誤訊息。
  6. GitHub Pages 的 repo 是公開的。前端只能有 GAS 網址，其餘一律不得出現在 repo。
- 「LINE webhook 打到 GAS 能穩定運作」（GAS 回應為 302 轉址）與「GitHub Pages 前端以 text/plain POST 呼叫 GAS」是尚未驗證的假設，必須在階段 0B 實測，不通就停下來跟我討論替代方案，不要硬做下去。

## 五、狀態定義與達標判定
每一個進程級別、每一個技能章，對每位小狼都只有四種狀態，查詢端與後台統一使用：
- 已頒發：頒章紀錄有這一筆。顯示頒發日期。
- 已完成待頒發：啟用中的項目全部完成，但尚未頒章。
- 進行中：至少完成 1 項但未全部完成。
- 未開始：0 項完成。
進程級別順序：剛入團 → 羚羊 → 狼 → 鹿 → 豹（附錄第 37 點）。進程另有規則：目前級別的下一級，即使 0 項完成也視為「進行中」（沒有任何頒章的小狼，「剛入團」為進行中）。已經拿到羚羊以上的小狼，「剛入團」視為已通過（不寫入頒章紀錄，顯示「已晉級，視為通過」）。

達標（可頒章）判定：
- 剛入團：該級啟用項目全部完成，且入團後出席次數達「剛入團所需出席次數」（預設 4，請假不算）即達標，頒發黃領巾。
- 羚羊級：該級啟用項目全部完成，剛入團已頒發，且剛入團頒發日之後出席次數達「晉級所需出席次數」即達標（不套用晉級間隔月數）。其中「參加幼童軍團集會至少4次」由出席紀錄自動判定：**剛入團頒發日之後（不含當天）**出席（請假不算）滿設定次數即視為完成，完成日期為第 4 次出席日；剛入團還沒頒發就不會自動完成（附錄第 64 點）；這是計算結果，不寫入完成紀錄，出席被修改時自動重算；團長也可人工簽核，兩者取較早日期。
- 狼、鹿、豹級：該級啟用項目全部完成，且距上一級的「頒發日期」滿設定的晉級間隔月數，且上一級頒發日之後（不含當天）出席次數達設定的「晉級所需出席次數」（請假不算；0 表示不要求）。以頒發日期起算，不是登錄時間。達標日期為上述條件都滿足的最早日期。
- 技能章：該章啟用項目全部完成。
- 停用的項目不計入完成度與達標判定。
- 達標只代表「可頒章」，不改變任何資料，一律等團長登錄頒章。

## 六、查詢端（家長/小狼）
1. 註冊與綁定（附錄第 31 點，2026-11-14 起的新方式）：家長與服務員自己在網站註冊、送出申請，團長在後台審核。
   - 註冊：開啟網頁 →「登入」→「註冊新帳號」→ 選身分（家長／服務員；家長兼服務員選服務員，或先選家長再由團長用 7.9 方式一調整）→ 填資料：家長填孩子姓名（可多位，最多 5 位）與稱呼；服務員填姓名，可勾「我也有孩子在團裡」一起填孩子 → 帳號名稱、密碼 → 有填孩子時顯示個資告知同意畫面，勾選同意後才建立帳號 → 送出申請。
   - 送出後帳號即可登入，但只看到「等待團長審核」與自己的申請狀態；團長核准後才看得到孩子（或進入後台）。被退回時顯示「未通過」與團長備註。
   - 已有帳號、要加第二個孩子：登入後在「我的資料」填孩子姓名 → 確認告知同意 → 送出申請，同樣由團長審核。
   - 舊方式保留：團長仍可產生綁定碼，家長用「我有綁定碼」註冊，不需審核。邀請碼已拿掉（附錄第 33 點），只剩 setup() 產生的第一位團長邀請碼，也在「我有綁定碼」輸入。
   - 不同意就不建立帳號、不綁定，也不留下任何紀錄。
   - 同意時間與版本寫入綁定紀錄。告知內容改版後，已綁定的帳號下次登入時要重新確認一次。
   - 一個帳號可綁多位小狼，一位小狼可被多個帳號綁定（例如爸爸、媽媽各自註冊）。綁多位時上方可切換。
   - 登入：帳號名稱＋密碼，可勾選「記住我」（依設定的登入保持天數）。忘記密碼時畫面提示「請聯絡團長取得臨時碼」，並提供「用臨時碼設定新密碼」入口。
2. 首頁由上到下（最重要的放最上面，先回答家長「我的孩子下一步要做什麼」）：
   - 基本資料：姓名、小隊、入團日、入團至今多久（X 年 X 個月）、目前級別。
   - 「下一步挑戰」：列出下一級尚未完成的 3 個項目。

## 七、團長後台
身分判斷：所有人都用帳號登入；新註冊的帳號預設只有家長身分。後端確認登入帳號存在「管理員」分頁才可進後台。管理員身分由團長在後台指定（見 7.9）。

權限：團長可做全部操作。服務員只能簽核、撤銷自己的簽核、點名、查看名單與總覽、列印簽核單；不可管理名單、綁定碼、管理員、項目、設定、個資處理，也不可頒章。

身分並存：同一個帳號可以同時是管理員又綁定了小狼，此時以管理員身分為主：登入後預設進後台，畫面上方有「切換到家長畫面」的按鈕。

### 7.1 首頁
- 最上方固定顯示「待頒章」名單與數量，以及「快達標」名單（依設定門檻）。
- 顯示系統提示：通知未送達、項目總表格式錯誤列數、設定值不合理、上次備份時間與是否成功、離團已超過設定天數尚未處理個資的小狼。

### 7.2 小狼管理
- 新增/編輯/標記離團。入團日由團長填寫，可填過去日期。新增時由後端自動產生綁定碼。標記離團時記錄離團日，綁定碼立即失效。
- 列表顯示入團日，可依入團日或小隊排序篩選。
- 小隊：團長先在「小隊設定」建立小隊清單（新增、改名、刪除、調整順序），新增或編輯小狼時只能從清單中選擇（或不分小隊）。改名時該小隊的所有小狼一起更新；還有在團小狼的小隊不可刪除。清單存在「設定」分頁的「小隊清單」（頓號分隔），也可直接在試算表修改。

### 7.2-1 註冊審核（團長專用，附錄第 31 點）

- 孩子：選「新增小狼」（可修正姓名、選小隊、填入團日，系統同時產生綁定碼）或「連結到現有小狼」（有同名在團小狼時預設選這個並提示，避免爸爸媽媽各自申請造成重複），核准後綁定申請人帳號，同意時間與版本沿用申請時的紀錄。
- 服務員：確認顯示姓名後核准，申請人成為服務員（已經是管理員則直接結案）。
- 退回：可填原因（申請人看得到）。

### 7.2-2 小隊輔、正副小隊長、批次匯入、升團（附錄第 45 點）

### 7.3 綁定碼（舊方式，保留）
- 後端產生亂碼，長度依設定，只用大寫英文與數字並排除易混淆字元（0、O、1、I、L），保證不重複。可用次數依設定，用完失效。
- 後台可重新產生（舊碼立即失效）、查看誰綁了這位小狼、解除某個綁定，並提供「複製給家長的說明文字」按鈕。

### 7.4 簽核
簽核是服務員在團集會現場用手機操作的功能，速度優先：三步內完成、不需要打字、送出後留在原畫面可繼續簽下一批。
- 小隊批次簽核（主要用法）：選小隊（或全團）→ 勾選一個或多個項目 → 勾選一位或多位小狼（預設全選該小隊，可取消個別）→ 填日期（預設今天）→ 一次送出。已完成的組合自動略過不重複寫入，送出後顯示「新增幾筆、略過幾筆」。
- 單人簽核：選小狼→看到全部啟用項目→勾選完成並填日期，簽核人自動帶入。
- 項目選擇要好找：可依級別與大項篩選，並把「最近簽過的項目」放最上面。
- 可跨級簽核：進程依團集會實際完成的內容簽，不受小狼目前級別限制（例如羚羊級小狼已完成豹級的工具項目，可直接簽豹級該項）；目前級別仍只依頒章決定，跨級項目會讓該級顯示為「進行中」（附錄第 28 點）。
- 撤銷簽核：可取消誤簽，寫入操作日誌。剛送出的那一批提供「復原」按鈕。
- 總覽：小狼×級別的完成度矩陣，可依小隊篩選。
- 列印簽核單：可依小狼或依小隊，列印某一級的簽核單（A4），供貼進或夾進紙本手冊。

### 7.5 頒章（頒發日期由團長設定）
- 頒章表單欄位：頒發日期（必填，預設今天，可改）、頒發場合（選填，例如「11 月團集會」）、備註（選填）。簽核人自動帶入。
- 頒發日期可填過去日期，不可早於該級別或該章最後一個項目的完成日期；填未來日期時要再確認一次。
- 頒發日期是儀式實際日期，登錄時間是系統寫入時間，兩者分開存。
- 批次頒章：同一場儀式可勾選多位小狼、多個級別或技能章，共用同一個頒發日期與場合，一次送出。
- 進程頒章成功後更新該小狼的目前級別。
- 修改與撤銷：團長可修改已登錄的頒發日期、場合、備註，也可撤銷整筆頒章（撤銷進程頒章後目前級別退回上一級）。兩者都寫入操作日誌並保留修改前的值。
- 頒發日期被修改或頒章被撤銷時，重新計算受影響小狼的達標狀態。

### 7.6 直接補登頒章（系統上線時用）

- 選小狼 → 選級別或技能章 → 填頒發日期 → 送出，直接寫入頒章紀錄。
- 同時把該級別或該章的所有啟用項目標記為完成，完成日期填頒發日期，備註註明「上線補登」。
- 補登進程級別時，較低級別若沒有紀錄，提示我是否一併補登。
- 補登不觸發任何推播通知。

### 7.7 項目管理（團長專用）

- 新增項目：選擇所屬級別或章名與大項，輸入內容，項目ID 由後端自動產生。
- 停用項目：不刪除，只把「啟用」設為否。停用後不顯示於查詢端、不計入完成度與達標判定，完成紀錄保留，重新啟用即恢復。項目不提供真正刪除。
- 調整順序：同一大項內可上移/下移，只改「排序」欄。
- 新增技能章或大項；修改技能章名稱或大項名稱時同步更新其下所有項目，項目ID 不變。
- 編輯「級別與章說明」的說明與晉級條件文字。
- 影響預覽：會影響達標結果的操作（新增、停用、重新啟用項目），送出前先顯示「這會讓 N 位小狼從已完成待頒發變成進行中／反之」並列出姓名，我確認後才執行。
- 已頒章的紀錄不受任何項目修改影響，不回溯、不撤銷。
- 每次修改寫入操作日誌（含修改前與修改後內容）。
- 提供「匯出項目總表為 CSV」「檢查項目總表」「重新載入項目」三個按鈕。
- 本團細項（進程細項分頁）：每個進程項目可在後台新增、修改、停用細項（分組、細項內容、通過標準、生活應用）。修改與停用以列號定位並核對原內容，試算表同時被改過時請團長重新整理。
- 技能章改名：有頒章紀錄的技能章不能改名（頒章紀錄以章名對應，不得改動頒章紀錄）。進程級別不能改名。
- 2026-11-15 已實作（`gas/ItemsAdmin.js`、後台「📝 項目管理」）。

我也可能直接在 Google 試算表修改「項目總表」「級別與章說明」「進程細項」「設定」「告知同意內容」，後端要能容錯：

### 7.9 管理員指定（團長專用）
團長在後台指定誰是管理員。提供兩種方式：

方式一：從已註冊的帳號中指定（對方已有帳號，例如家長兼服務員）
- 列出所有已註冊帳號：帳號名稱、稱呼、綁定的小狼姓名。可搜尋。

方式二：對方還沒有帳號 → 請對方自己註冊選「服務員」，團長在「註冊審核」核准（7.2-1）。邀請碼功能已拿掉（附錄第 33 點）。

管理既有管理員：

- 系統至少保留一位團長：不可移除最後一位團長，也不可把最後一位團長降為服務員。
- 團長不可移除自己；要卸任須先指定另一位團長，由對方操作。

通知與紀錄：
- 指定成功、角色變更、被移除時，若當事人已連結 LINE，推播一則訊息給當事人。
- 有人使用邀請碼成為管理員時，推播通知建立該邀請碼的團長。
- 以上所有操作寫入操作日誌。

第一位團長：

### 7.10 個資處理（團長專用）
針對離團小狼或家長提出要求時使用。兩種處理都要二次確認，並要求我輸入該小狼姓名才能執行。
- 匿名化：把姓名改為「已離團小狼」加流水號、清空小隊、刪除該小狼的所有綁定紀錄、狀態改為已匿名。完成紀錄、頒章紀錄、出席紀錄與額外出席保留，僅供團內統計，無法再對應到個人。
- 完全刪除：從小狼名單、綁定紀錄、完成紀錄、頒章紀錄、通知紀錄、出席紀錄、額外出席中移除該小狼的所有列。操作日誌中與該小狼相關的紀錄，把姓名替換為「已刪除」。
- 刪除或匿名化的操作本身寫入操作日誌，但只記「某團長於某時間處理了一位小狼的個資」，不記姓名。
- 執行前顯示會影響幾列資料；執行後提醒我：既有的每週備份檔仍含這位小狼的資料，會在保留份數輪替後消失，並提供「立即刪除所有舊備份並重新備份」的選項。
- 小狼離團超過設定天數仍未處理時，在後台首頁提醒我。
- 家長端的「解除綁定」只移除該帳號的綁定，不影響小狼資料。

### 7.11 備份與試算表權限
- 每週排程把整份試算表複製到我指定的 Google 雲端硬碟資料夾，檔名含日期，只保留設定的份數，超過自動刪除最舊的。資料夾 ID 放 Script Properties。
- 後台提供「立即備份」按鈕，並顯示上次備份時間與結果。備份失敗時推播通知團長。
- 提供「檢查試算表權限」功能：若試算表或備份資料夾被設成「知道連結的任何人」可檢視或編輯，在後台首頁顯示紅色警告。
- 對重要分頁的標題列設保護，避免誤刪欄位。

### 7.12 帳號管理（團長專用）
- 列出所有帳號：帳號名稱、稱呼、綁定的小狼、身分（家長/服務員/團長）、建立時間、最後登入時間。可搜尋。
- 重設密碼：產生一次性臨時碼（字元規則同綁定碼，長度 8，有效時數依設定），提供「複製給家長的說明文字」按鈕，由團長自行用 LINE 官方帳號傳送。產生臨時碼時，該帳號所有登入憑證立即失效。
- 停用／重新啟用帳號：停用後無法登入，綁定紀錄保留。
- 刪除帳號（家長要求時）：刪除帳號、其登入憑證與綁定紀錄；小狼資料不受影響。若該帳號是管理員，適用 7.9 的最後一位團長保護。

### 7.13 集會行事曆與點名

點名（團長與服務員，團集會現場用手機）：
- 速度優先，比照簽核：開啟點名畫面預設選「今天」的集會（今天沒有集會時選最近一場）→ 可依小隊篩選 → 每位小狼一列，點一下切換「出席 → 遲到 → 請假 → 空白」→ 送出（遲到算出席，附錄第 61 點）。不需要打字。

- 「空白」代表沒來也沒請假；系統不記錄缺席（空白就是沒有這筆出席紀錄）。出席與請假分開計算。

查看：

出席與進程的關係：

出席率（家長端與後台都顯示）：

## 八、LINE 官方帳號主動通知
觸發時機：
1. 即時：每次簽核送出後，重算受影響小狼的狀態，新達標就通知。
2. 每日排程：依設定時間每天掃全部在團小狼，抓「項目早就全過、今天剛滿晉級間隔」的情況。提供安裝與移除 trigger 的函式。

通知規則：
- 達標 → 推播給所有已連結 LINE 的管理員。用 Flex Message：小狼姓名、小隊、入團日、達標的級別或章名、達標日期、一顆「前往頒章」按鈕（開啟網頁，登入後直接跳到該小狼的頒章表單）。
- 同一次觸發有多位小狼達標 → 合併成一則。
- 家長不接收任何 LINE 推播；頒章結果與日期在網頁「已經拿到的」顯示。
- 同一小狼同一級別或章只通知一次（查通知紀錄）。因撤銷簽核、撤銷頒章或項目修改而不再達標時，清除該通知紀錄，重新達標可再通知。
- 因項目修改造成的批次狀態變動，合併成一則摘要通知管理員，不逐人推播。
- 達標超過設定天數仍未頒章 → 再提醒管理員一次，之後不再提醒。
- 推播失敗（未加好友或已封鎖）寫入操作日誌，並在後台首頁標示「通知未送達」。沒有任何管理員連結 LINE 時，在後台首頁提示。

省推播額度：
- 推播計入每月免費額度（輕用量 200 則），回覆不計。預估：30 位小狼、進程一年頒發兩次、技能章一季一次，每月用量遠低於免費額度。
- 做關鍵字回覆：已連結 LINE 的管理員輸入「可晉級」→ 回覆達標未頒章名單；輸入「快達標」→ 回覆快達標名單；輸入「點名」→ 回覆今天或下一場集會、已請假名單與直達點名頁的連結（附錄第 63 點）。任何人輸入「進度」→ 只回覆網頁連結，不回任何個資。
- 未連結 LINE 的人（含家長）輸入「可晉級」「快達標」「點名」不回名單。
- SETUP.md 說明如何在圖文選單放「查進度（開網頁）」「可晉級名單」按鈕。

## 九、安全與個資（不可妥協）
- 前端只送登入憑證；後端以憑證雜湊查出帳號ID。絕不相信前端傳來的帳號ID 或身分。
- 密碼只存加鹽多次雜湊；密碼、臨時碼、登入憑證不得出現在日誌、錯誤訊息或 API 回應中。
- 查詢端 API 只回傳該帳號已綁定小狼的資料。
- 後台每一支 API 都要在後端檢查管理員身分與角色，不能只靠前端隱藏按鈕。指定、變更、移除管理員與個資處理的 API 必須在後端確認操作者是團長。
- API 不回傳其他人的帳號ID、LINE userId 給前端；需要指認對象時用後端產生的內部代號。
- 登入密碼錯誤（依帳號名稱計）、綁定碼與邀請碼輸入錯誤（已登入依帳號計，未登入依全站計）達設定次數即鎖定設定的分鐘數。
- 登入錯誤訊息一律為「帳號或密碼錯誤」，不透露帳號是否存在。
- 所有金鑰、Channel token、webhook 密鑰、備份資料夾 ID 放 Script Properties，不進版控、不寫進前端。
- 只存孩子的姓名、小隊、入團日、進程紀錄與出席紀錄，以及家長的帳號名稱、稱呼與密碼雜湊；管理員另存姓名與（自願連結的）LINE userId。不收集生日、身分證字號、電話、地址、照片。回傳給前端的資料欄位採白名單。
- 沒有同意紀錄就沒有綁定；同意版本過期要重新確認。
- 錯誤訊息不得洩漏其他小狼是否存在，也不得透露輸入的是綁定碼還是邀請碼格式。
- 試算表與備份資料夾只分享給必要的人，不可開「知道連結的任何人」。服務員透過後台操作，不需要試算表的編輯權。
- docs/PRIVACY.md 的告知文字是草稿，請在文件開頭註明「上線前需由團長確認內容，並視需要請教熟悉個資法的人」。

## 十三、工作方式
分階段進行，每個階段結束先停下來向我回報「做了什麼、怎麼驗證的、需要我做什麼」，等我說繼續再往下。每個階段完成都要 git commit，訊息用繁體中文說明變更。

- 階段 0A：git init、存 docs/SPEC.md、建立專案結構、CLAUDE.md、data/items.csv，並列出你對規格的疑問或你認為有風險的地方。
- 階段 0B 技術驗證：只做最小可行的三件事並請我實測 —— ① GitHub Pages 上的網頁能以 text/plain POST 呼叫 GAS 並取得回應（手機與電腦瀏覽器都測） ② 測試帳號註冊、登入、記住登入、憑證過期後回到登入畫面 ③ LINE webhook 打到 GAS，輸入任意文字能收到回覆。寫一份只涵蓋這三件事的精簡設定步驟給我。三件事全通才往下；任何一件不通，停下來跟我討論替代方案。
- 階段 1：純邏輯函式與 Node 測試，測試全過。
- 階段 2：GAS 後端基礎（setup、設定讀取、帳號註冊登入與憑證、查詢 API、綁定與告知同意）。
- 階段 3：查詢端前端（註冊與登入、告知同意畫面、首頁各區塊、進程頁、技能章頁、出席紀錄、我的資料、列印簽核單）。
- 階段 4A 核心後台：首頁、小狼管理、綁定碼、簽核（含小隊批次）、頒章表單、補登、集會行事曆與點名、管理員指定的方式一與方式二（邀請碼）與既有管理員管理、連結 LINE 通知、帳號管理（重設密碼）、個資處理、備份與權限檢查。同時把 SETUP.md、TESTING.md、PRIVACY.md 寫到足以上線的程度。
- 里程碑一（可上線試用）：階段 4A 完成後停下來。我會實際上線給團裡試用，並回報家長與服務員的使用狀況。在我明確說「繼續做 4B」之前，不要動後面的階段；這段期間只修試用發現的問題。
- 階段 4B 管理介面：項目管理、設定畫面。里程碑一期間，這些需求我會直接改試算表處理，所以第七節 7.7 的試算表容錯必須在階段 2 就做好。
- 階段 5：LINE 主動通知、webhook 關鍵字回覆、每日排程。
- 階段 6：全部文件定稿。

46. 最高權限鎖在 admin（2026-11-15 團長決定）：
   - 系統有 `admin` 帳號（試算表選單產生的團長預設帳號）時，它是最高權限帳號：**只有 admin 可以指定團長、把團長降為服務員、移除團長**；其他團長只能管理服務員，其餘團務操作不變。
   - admin 本身不能被任何人（包含其他團長）降級、移除、改名、停用、刪除或產生臨時碼；要重設 admin 密碼只能從試算表選單。admin 也不能把自己降級或移除（沿用原規則）。
   - 其他團長的帳號也不能被非 admin 的人停用、刪除或產生臨時碼（避免繞過）。
   - 還沒建立 admin 帳號時照原本規則（任何團長都能管理團長），避免沒有人能指定團長。試算表選單「把帳號設為團長」不受影響（能開試算表的人就是擁有者）。
   - 後端檢查在 `Logic.validateAdminChange(…, ownerId)` 與 `guardOwner_`；`me.isOwner`、`adminList.ownerExists`／`admins[].owner` 供畫面顯示，前端只是隱藏按鈕。

56. 網頁可以直接由 GAS 提供（2026-11-16 團長要求「載體是 GAS」）：
   - Apps Script 專案裡新增 HTML 檔「Index」（內容＝`dist/Index.html`，和 `web/index.html` 完全相同）。`doGet` 有這個檔就回傳網頁（`HtmlService`），沒有就回原本的文字。網站網址就是 GAS 部署網址（`…/exec`）。
   - 同一份網頁自動判斷環境：由 GAS 提供時用 `google.script.run.apiFromPage` 呼叫後端（和 `doPost` 同一套 `handleApiBody_`，登入與權限檢查完全相同）；放在 GitHub Pages 時照舊用 `fetch`。兩種可以並存。
   - 好處：網頁與後端在同一個專案、同一次部署，不會再發生「網頁是新的、後端是舊的」而出現「不支援的操作」。
   - 分享連結：由 GAS 提供時用 `…/exec?p=notices`（或 `#notices`），`p` 可為 notices、progress、badges、about、calendar、events。
   - **安全**：網頁由 GAS 提供後，訪客可以用 `google.script.run` 呼叫所有「名稱不是底線結尾」的函式，因此：`setup()` 不回傳內容（邀請碼只寫在執行記錄；內部用 `setupCore_`）；`dailyJob`／`weeklyBackup` 一小時內重複呼叫會略過且不回傳內容（內部用 `runDaily_`／`runWeekly_`）；選單函式一律先取得試算表畫面（網頁情境會失敗）才動作。**之後新增任何不是底線結尾的函式，都要當成「任何訪客都能呼叫」來設計。**
   - 已知限制：GAS 會在頁面最上方顯示一條「這個應用程式是由 Google Apps Script 的使用者建立」的灰色橫幅，無法移除；網址較長。

58. GAS 版太慢的修正（2026-11-17，團長回報「載入中」太久）：
   - 原因一：每讀一個分頁就重新開一次試算表（`openById`），後台首頁一次請求開了 12 次。改為同一次執行只開一次、每個分頁只找一次（`SS_CACHE_`、`SHEET_CACHE_`）。

   - 原因三：很少變動的分頁（項目總表、級別與章說明、進程細項、設定）每次都重讀。改為暫存 10 分鐘（CacheService，單一分頁超過約 95KB 不暫存）；經由系統寫入時立即清除，團長直接在試算表編輯時由簡易觸發器 `onEdit` 清除，`setup` 也會清除。

72. 後端版本檢查與部署方式（2026-11-19，團長：「有沒有簡單處理的方式，未來一定也會遇到」）：
   - **起因**：網站的後端網址指向另一個舊 Apps Script 專案的部署，團長貼上新程式、執行 setup 都在另一個專案，網站卻一直跑舊程式而沒有任何提示。已改連團長維護中的專案（`GAS_URL` 換成新部署），LINE webhook 網址需同步更換。
   - **版本檢查**：後端 `APP_VERSION`（gas/Config.js）與網頁 `APP_VERSION`（web/index.html）兩邊寫同一個版本號；`me` 回傳 `serverVersion`、`ping` 回傳 `version`。團長登入後台時兩邊不一致，首頁「系統提示」出現紅色提醒與部署步驟。舊版後端沒有版本號，也會被當成不一致而提醒。
